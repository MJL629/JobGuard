## 一、已经完成并实际验证的能力

### 1. 对话构建画像

- 首次进入聊天会由后端创建 `profile_building` 会话并主动提问，不再等待用户先发一句话。
- 对话会继续追问岗位方向、城市、薪资、技能，以及简历之外的项目、实习、比赛、科研和工作经历。
- “偶尔正常加班可以，但不接受长期高强度加班”会拆分保存为：
  - 加班接受度：`偶尔可以`
  - 强度上限：`排斥长期/高强度`
- 高影响约束会先复述原意并请求确认，确认后才持久化。
- 同一句同时包含约束与项目经历时，经历不会再被确认分支丢弃。
- `profile_building` 会话中的自我描述优先进入画像流程；“简历里没写的项目”不再被误判为“生成简历”。

2026-08-04 浏览器实测：画像页显示“可接受偶尔正常加班；不接受长期或高强度加班”，并持久化了一条“校内智能问答比赛项目”补充经历。

### 2. 多份简历保存与解析

- 支持 PDF、扫描 PDF、DOCX、TXT、Markdown、PNG、JPG、JPEG、WEBP。
- 原文件、SHA-256、解析器、OCR 状态、已识别字符数、结构化结果和失败原因均会保存。
- 结构化解析失败时原文件仍保留，状态标为“需要复核”，不会再把上传失败等同于文件丢失。
- 同一用户可保存多份简历，并切换唯一主简历。

2026-08-04 真实 API 实测：上传两份不同的合成 DOCX，均返回 `code=0`、`parse_status=parsed`；列表为 2 份，主简历恰好 1 份。

### 3. 岗位截图与连续追问

- 优先调用现有智谱多模态模型 `glm-4v-flash` 识别岗位截图。
- 多模态不可用时自动降级到本地 RapidOCR，并在响应中返回 `analysis_mode` 与安全化的降级原因。
- 截图识别出的公司、岗位、JD 和风险报告会进入当前聊天会话上下文。
- 用户随后说“确定，帮我分析”“值不值得投”等短句时，会复用上一次截图结果，不再要求重新输入公司和岗位。

实测截图识别出“广州格物知新人工智能科技有限公司 / Agent 应用研发工程师”，本次运行使用 `local_ocr` 降级模式；后续“确定，帮我分析”成功复用上下文。

### 4. 定向简历与模板

- 内置四套模板：商务蓝分区、标准表格式、极简技术风、淡紫专业风。
- 支持用户上传自己的 DOCX 模板。
- 模板选择会同时影响可编辑 DOCX 与 PDF 样式。
- 生成时会使用画像、补充经历和目标岗位，并对学校、技能、项目、量化数字执行事实保护。
- 大模型核查不可用或生成内容无法修正时，会丢弃不可靠草稿，使用已持久化事实构造安全版本，而不是保存假成功结果。
- 生成超时由前后端统一放宽到 240 秒，可分别下载 DOCX、PDF 或 Markdown。

四个内置模板均已生成 DOCX，使用 Word 转 PDF 后逐页检查：中文字体正常，无重叠、截断、表格断裂或缺字。

### 5. LangGraph 与 MCP

- 生产 LangGraph 包含真实执行的 `classify_intent → build_execution_plan → apply_evidence_gate` 主链，惰性编译一次，不存在重复构图、空业务节点或伪造执行链。
- 业务事务由聊天 API 显式分发到画像、岗位分析、推荐和简历生成流程。
- `GET /api/agent/graph` 返回实际运行节点与边。
- `GET /api/agent/tools` 返回可执行工具及 MCP stdio 启动信息。
- MCP 服务暴露企业证据、岗位检索、岗位要求分析、学习资源、人工核验计划和工具状态共 6 个协议工具；应用内 Agent 与 MCP 复用同一套真实实现。

MCP 启动命令：

```powershell
cd E:\jobguard\jobguard\backend
.\.venv\Scripts\python.exe -m app.mcp_server
```

## 二、真实数据和外部工具边界

- 北京市公共数据开放平台的正式 CSV 已导入 MySQL：232 条计算机相关有效记录，来源 URL 和数据集标识保留。
- 企业证据已关联 232 个岗位、126 家公司；页面只展示数据库中实际存在的证据来源。
- 国家企业信用信息公示系统仍是人工核验入口，不会把个人登录 Cookie、验证码或实名信息写进 Agent。
- `search_company_info` 是可调用工具，但只能返回已入库的真实证据；无来源时返回 `unknown/no_evidence`。
- 目前没有把实名网站浏览器会话做成无人值守 MCP。若页面需要验证码或访问许可，系统不会绕过。
- 社保人数、劳动仲裁数量、公司口碑等字段没有可核验来源时必须为空或“未核验”，不能由大模型猜测。

## 三、你明天的验收顺序

### A. 画像语义与深挖

1. 打开 `http://127.0.0.1:5173/chat`，新建或继续画像会话。
2. 输入：`我不是完全拒绝加班，但不接受长期高强度加班。`
3. 确认系统先复述限定条件；回复“正确”。
4. 再输入一段简历中没有的项目/实习/比赛经历，包含“目标、你的角色、做了什么、用了什么工具、结果”。没有真实数字时明确说没有量化数据。
5. 打开 `/profile`，确认工作强度没有变成“完全不接受加班”，补充经历已出现。

验收标准：原意不被扩大；确认前不写硬约束；确认后刷新页面仍存在；经历进入 MySQL 并可在画像页看到。

### B. 多份简历

1. 在 `/profile` 上传第一份 PDF 或 DOCX。
2. 再上传第二份不同简历。
3. 检查两份文件均出现在“已保存简历”，并切换主简历。
4. 可再上传一份只有图片的扫描 PDF，检查是否显示 OCR 字数或明确的中文失败原因。

验收标准：文件不丢失；重复文件提示去重；解析失败也显示“已保存/需复核”；始终只有一份主简历。

### C. 岗位截图连续分析

1. 在 `/chat` 点击图片按钮，上传包含公司名和岗位名的清晰招聘截图。
2. 检查回复中的公司、岗位、识别模式和风险结论。
3. 直接回复：`确定，帮我分析，值不值得投？`

验收标准：第二句话复用前一张截图；明确给出“值得投/谨慎投/不优先”；没有来源时明确写未联网核验，不虚构数字。

### D. 定向简历

1. 确保画像至少有技能和一段真实经历，并在岗位页选择一个目标岗位。
2. 打开 `/resume`，依次选择四套内置模板生成。
3. 分别下载 DOCX 和 PDF，检查模板视觉确实不同。
4. 上传自己的 DOCX 模板，再生成一次。

验收标准：生成结果只包含画像中能追溯的事实；不同模板的 DOCX/PDF 有不同样式；下载文件可打开；失败时出现中文原因而不是假成功。

### E. 工具与来源

登录后访问：

- `http://127.0.0.1:8000/api/agent/graph`
- `http://127.0.0.1:8000/api/agent/tools`

在岗位分析页检查“可核验来源”和“Agent 工具调用记录”。

验收标准：工具状态与真实来源一致；来源为 0 时不能显示已核验；链接可打开并能支撑对应结论。

## 五、仍然存在的产品边界

- `glm-4v-flash` 是否可用受当前模型账户权限和上游状态影响；本地 OCR 是真实降级能力，但不是多模态理解的等价替代。
- 动态、登录或验证码岗位网页不能保证自动抓取，仍需粘贴 JD 或上传截图。
- 免费官方背调只能覆盖可公开、可核验的数据；实名且带访问控制的网站目前不能无人值守查询。
- 自定义 DOCX 模板会保留其页面设置与样式定义，但复杂文本框、宏和特殊布局不能保证完全自动填充。
- 岗位数据需要定期导入新官方文件，否则截止日期过后可推荐岗位会逐渐减少。
# 2026-08-08 企业背调真实联网补强

- `search_company_info` 不再只读 MySQL：分析岗位时会实际调用两个免费公开来源。
- 官方来源一：全国公共资源交易平台数据服务，按企业全称查询政府采购/公共资源交易主体及成交记录。
- 公开检索来源二：Microsoft Bing RSS，只保留标题或摘要中包含企业全称的结果和原始 URL；仅作线索，不生成员工口碑评分。
- 页面已区分“官方来源”“已联网查询”“已查询无结果”“受访问控制”“无公开统一接口”和“本次查询失败”。
- 国家企业信用信息公示系统、中国裁判文书网等存在登录/验证码访问控制，系统不会绕过验证，也不会把人工入口冒充自动查询结果。
- 社保人数没有稳定、无需授权的全国公开接口，继续保持未知，不由模型补全。
- 联网适配器单次请求超时收紧为 8 秒，并增加 10 分钟进程内缓存；岗位分析前端超时提高到 120 秒，避免真实联网任务被 30 秒前端超时误杀。
- 从岗位库进入分析时会把原岗位 ID 传给后端，只新增分析记录，不再复制或覆盖官方岗位；本轮浏览器回归产生的 3 条重复岗位已清理，相关分析重新关联到原岗位 80。
- 实测岗位 80：两个实时适配器均被调用；公共交易平台返回“已查询无结果”，公开网页检索保留 5 条企业全称来源；Agent 工具记录显示“实时适配器 2 个”。

验收方式：进入 `/jobs/analysis/80`，点击“开始真实分析”，检查各卡片状态、来源链接和 `search_company_info` 工具调用记录。

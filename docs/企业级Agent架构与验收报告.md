# JobGuard 企业级 Agent 架构与验收报告

> 更新日期：2026-08-08  
> 说明：本文只记录已经落地并可验收的能力；人工核验入口、Mock 降级和未来计划不会标为已完成。

## 1. 当前真实完成度

JobGuard 已从“前端页面 + 大模型单轮回答”升级为有真实业务闭环的求职 Agent：

1. 对话和简历共同补充用户画像，并将画像、深访进度、多份简历和经历持久化到 MySQL。
2. 岗位数据库检索、画像匹配、岗位截图识别、岗位风险分析和来源展示形成可回溯链路。
3. 定向简历必须基于已保存画像和目标岗位生成，支持四套内置模板、用户 DOCX 模板、DOCX/PDF 下载和事实保护。
4. LangGraph 真实执行“意图分类 → 确定性任务规划 → 证据/风险门禁”，业务写入仍由 FastAPI 事务层控制。
5. 应用内有 8 个可执行工具，其中 6 个同时通过 MCP stdio 暴露；写入型简历工具要求用户确认。
6. Agent 运行、工具调用、失败步骤、耗时和确定性流程评价已持久化，并在 `/agent-ops` 展示。

当前仍不是“全部自动联网背调系统”。需要登录、验证码或实名认证的网站保留为人工核验入口；没有来源时必须返回未知，不能让模型猜测社保人数、仲裁数量或口碑。

## 2. 产品业务闭环

```mermaid
flowchart LR
    U[用户对话/简历/岗位链接或截图] --> G[LangGraph 意图分类]
    G --> P[确定性任务计划]
    P --> E[证据与风险门禁]
    E --> A{业务流程}
    A -->|画像| PR[深度追问/约束确认/经历入库]
    A -->|岗位| JA[解析 JD/企业证据/匹配与风险]
    A -->|推荐| JR[数据库检索/画像差异化评分]
    A -->|简历| RG[人工确认/事实保护/模板生成]
    A -->|建议| CA[画像缺口/可核验学习资源]
    PR --> DB[(MySQL)]
    JA --> DB
    JR --> DB
    RG --> DB
    CA --> DB
    E --> T[应用工具注册表]
    T --> MCP[MCP stdio]
    A --> O[AgentRun/ToolTrace/Evaluation]

    O -.显式启用且仅传元数据.-> LS[LangSmith]
```

## 3. 六项标准对应结果

### 标准一：解决真实问题

- 明确用户需求：画像不完整、岗位信息不透明、推荐理由雷同、简历无法针对岗位调整。
- 完整流程：信息采集、确认、持久化、岗位检索、证据门禁、生成、下载、复盘均有真实接口和数据库状态。
- 可评估：生成是否完成、工具是否成功、来源数量、耗时、失败步骤均可查询。

### 标准二：完整后端工程体系

- API：FastAPI + OpenAPI，前后端接口已打通。
- 数据库：SQLAlchemy + Alembic + MySQL；Agent 运行、工具轨迹、评价和画像深访记忆有迁移。
- 权限：access token 决定真实用户，客户端传入的 `user_id` 不再作为身份依据。
- 异常与并发：中文错误、限流/并发控制、SSE 结构化事件、长耗时简历生成 240 秒边界。
- 日志与可观测性：数据库运行记录、失败步骤和可选 LangSmith 元数据追踪。

仍需 P1：长耗时生成目前仍是同步请求；高并发生产部署应引入 Redis + Arq/Celery 的持久队列、幂等键、取消和有限重试。

### 标准三：Agent 核心能力

- LangGraph 主链实际运行三个节点，不存在重复构图、空节点或声明后未执行的节点。
- 任务计划根据画像、岗位、推荐、简历和职业建议五类意图生成不同步骤。
- 证据门禁禁止无来源数字；简历写入要求人工确认；高影响画像约束确认后才能持久化。
- 工具不是展示项：注册表负责参数校验、权限注入、执行、结果和失败轨迹。

当前采用“确定性主图 + 领域工具/服务”，没有为了简历包装而堆多个互相对话的 Agent。未来只有在研究循环确实需要并行证据采集时，才增加 Researcher/Verifier 子图。

### 标准四：上下文工程

- Task Context：当前会话类型、上一份岗位截图/分析、执行计划和证据策略。
- User Memory：画像、偏好、约束、技能、经历、深访完成进度和多份简历。
- Knowledge/Data：MySQL 岗位、企业证据、来源链接和 Chroma 现有知识数据。
- Tool Results：工具结果及来源数量写入调用轨迹；聊天短句可继续复用上一轮岗位上下文。
- Resume Grounding：学校、技能、项目和数字必须能回溯到画像/简历/补充经历。

### 标准五：可观测性和评估

- `/agent-ops` 展示运行总数、流程成功率、工具成功率、平均耗时、失败步骤和错误类型。
- `agent_runs`、`tool_call_traces`、`agent_evaluations` 持久化运行和确定性门禁结果。
- 输入/结果摘要会脱敏，不存 API Key、密码、Cookie、userKey、token 或简历全文。
- 当前模型网关不能稳定取得 provider usage，因此成本明确显示 `provider_usage_unavailable`，不会伪造 token 和费用。
- LangSmith 默认关闭；显式启用后只发送工作流元数据，不发送原始聊天、画像和简历正文。

仍需 P1：建立固定的离线金标集，评估意图准确率、画像字段保真率、推荐排序 NDCG、简历事实一致率和引用正确率。

### 标准六：人机协同

- 加班、强度等高影响约束先复述确认再保存。
- 写入型 `generate_targeted_resume` 工具必须 `confirmed=true`，否则拒绝执行并记录失败步骤。
- 企业官网/工商/裁判/执行信息保留可核验链接和人工复核步骤。
- 验证码、实名认证、对外投递和账号操作不做无人值守自动化。

## 4. 已接入工具

应用内 8 个工具：

1. `search_company_info`
2. `search_job_database`
3. `analyze_job_requirements`
4. `inspect_profile_gaps`
5. `recommend_jobs_for_profile`
6. `recommend_learning_resources`
7. `build_company_verification_plan`
8. `generate_targeted_resume`

MCP 暴露前 3 个、第 6、7 个，以及 `get_jobguard_tool_status`，共 6 个协议工具。涉及当前用户隐私或数据库写入的工具不直接通过无身份上下文的 MCP 暴露。

启动 MCP：

```powershell
cd E:\jobguard\jobguard\backend
.\.venv\Scripts\python.exe -m app.mcp_server
```

## 6. 用户验收顺序

1. 在 `/chat` 新建画像会话，不上传简历，连续回答教育、项目、比赛、证书、实习和 STAR 追问；刷新 `/profile` 检查持久化。
2. 输入“偶尔正常加班可以，但不接受长期高强度加班”，确认后检查画像没有被压缩为“不接受加班”。
3. 在 `/profile` 连续上传两份 PDF/DOCX，切换主简历，检查解析状态和反向追问。
4. 在 `/chat` 上传清晰岗位截图，随后只回复“继续分析，值不值得投”，确认复用上一轮岗位上下文。
5. 在 `/jobs` 检查不同岗位分数和理由不是固定值；打开分析页核对真实来源和“未核验”边界。
6. 在 `/resume` 选择目标岗位和四套模板之一，生成后分别下载 DOCX/PDF。
7. 打开 `/agent-ops`，确认上述操作产生运行记录、耗时、状态和失败步骤。

## 7. 尚未冒充完成的能力

- 国家企业信用信息公示系统等带登录/验证码的网站尚未成为无人值守 MCP 工具。
- 社保人数、劳动仲裁数量、公司口碑在无可核验来源时不会自动给出具体数字。
- 同步简历生成尚未迁移到 Redis/Arq 后台队列。
- 内容准确率和模型成本尚无完整金标集/usage 数据，页面会如实显示未知。
- 外部招聘站的动态页面不保证自动解析，仍支持用户粘贴 JD、上传截图或导入官方 CSV。

这些是下一阶段的工程项，不属于本轮假成功。
